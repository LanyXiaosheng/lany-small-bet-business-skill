# 小生意验证技能使用说明

`lany-small-bet-business-skill` 把想法变成一次有预算、有交付、有复盘的最小商业试验。

## 何时使用

有能力却不知道怎样收费；想验证一个副业；有人咨询但没有购买；手工服务重复出现，想判断何时产品化。

## 输入和产出

提供用户问题、现有解法、可触达的人、时间和现金上限。得到试验假设、服务说明、报价草案、触达文案、执行表和停止条件。它不替你寻找投资标的，也不自动发布或收钱。

## 完整示例（虚构演示）

输入：

> 使用 $lany-small-bet-business-skill。我会整理会议纪要。已有三位项目经理问过我模板，但没人买过。接下来一周只有六小时、最多花100元，不买广告。我想测试是否有人需要一次付费代整理。

示例方案：

- 假设：需要追踪跨部门行动项的经理，愿意为一份可验收的纪要整理付费；目前只有问题信号，没有支付证据。
- 本轮：准备一份虚构会议记录的前后对照，向愿意了解服务的人展示，不把收到提问算成交。
- 交付：客户提供经授权、脱敏的会议记录；返回行动清单，标明负责人、期限和待确认项；含一次范围内修订，不替客户作管理决定。
- 报价草案：每份99元，限制原始记录长度与交付工时；这是试验价，尚未验证能否覆盖沟通与返工。
- 文案草稿：“会议记了两页，最后还是不知道谁来做？我把一份示例纪要整理成负责人、期限、验收项三列。你可先看这个对照，若也需要整理，我可以说明本周试做的范围和价格。”
- 资源：准备样例一小时、沟通两小时、预留交付两小时、复盘一小时。现金预算100元是上限，不是必须花完。
- 记录：实际接触合适对象的人数、看到报价的人数、自然购买或熟人支持、沟通时间、交付与返工时间、是否验收。
- 暂停：六小时用尽即复盘，不靠追加投入追单；遇到未获授权的会议资料先停在资料接收前。
- 判断：有付费且能按范围交付，才进一步测试可重复性；无人看到完整报价，结论是触达不足；有人认真询问却不买，先核对原因，不能直接归因于价格。

示例没有虚构成交结果，也没有承诺一周能赚到钱。

## 方法取舍

早期免费可以测可用性，但不能直接证明支付意愿；收费可以测特定价格下的选择，但熟人支持不能等同自然需求。低频服务无需硬做复购或社群。

## 补充用法

加强价格实验与服务产品化判断，保留免费和收费的不同验证目标。调用示例：

> 使用 $lany-small-bet-business-skill。我已手工交付四次，但每次需求略有不同。请找可标准化部分，核算沟通与返工时间，设计一次报价试验，不预设必须做课程。

确认目标目录不存在后，可在未设置 `CODEX_HOME` 的默认环境下安装：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/LanyXiaosheng/lany-small-bet-business-skill.git ~/.codex/skills/lany-small-bet-business-skill
```

已设置 `CODEX_HOME` 时，将目标改为该目录下的 `skills/lany-small-bet-business-skill`。已有同名技能时先比较或备份，不覆盖。客户端发现技能后，使用 `$lany-small-bet-business-skill` 调用。
